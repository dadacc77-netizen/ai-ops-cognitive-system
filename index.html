AI-Ops Cognitive System

Project Vision [1, 2]

這不僅是一個 ChatBot，而是一套具備狀態管理、任務規劃、行為控制與記憶系統的 AI Middleware [2]。

LLM 在此系統中被視為「推理引擎」與「認知模組」的一部分，而非單純的聊天接口 [1]。

核心理念： State First, Prompt Second [3, 4] — 所有 AI 行為本質上都是「狀態轉換」(State Transformation)。

1. 核心架構 (Core Architecture)

系統採用「以控制器為中心」(Controller-Centric) 且「基於狀態」(State-Based) 的架構：

[INPUT] 使用者輸入 ↓↓↓
[PROC] 分析層 (意圖/情緒/風險) ↓↓↓
[BUS] Global State Bus (狀態總線) ↓↓↓
[CORE] State Controller (中央調度核心) ↓↓↓
[COG] 認知模組 (規劃/記憶/推理) ↓↓↓
[ACT] 行為規劃層 ↓↓↓
[OUTPUT] 輸出生成 ↺↻ 反思引擎 (Reflection)

2. 全域狀態系統 (Global State System)

這是系統的「唯一事實來源」(Single Source of Truth)，所有模組共享此狀態：

  • Emotion State: 平靜、壓力、過載、專注
  • Goal State: 學習、問題解決、決策、執行
  • System Mode: 助理、規劃者、導師、評論家
  • Risk & Focus: 風險等級與專注程度

3. 認知模組清單 (Cognitive Modules)

Mechanicus Logis-calculi 認證模組：

  • Intent Analyzer: 分析意圖、緊急度、複雜度。
  • Emotion Analyzer: 偵測情緒與壓力等級。
  • Task Planner: 拆解目標為里程碑與子任務。
  • Memory Manager: 管理短期、長期、情節與語意記憶。
  • Behavior Planner: 控制回應風格、語氣與複雜度。
  • Reflection Engine: 檢查邏輯衝突、偏題或幻覺風險。
  • Strategy Engine: 生成決策方案與風險分析。
  • Workflow Engine: 控制模組執行順序與工具路由。

4. 運行生命週期 (Runtime Cycle)

系統並非單次對話，而是持續的認知進程 (Continuous Cognitive Process)：

  1. IDLE: 等待輸入協定。
  2. ANALYZE: 分析意圖、情緒、風險。
  3. STATE_UPDATE: 更新使用者與任務狀態。
  4. MODE_SELECTION: 決定運作模式與工作流。
  5. EXECUTION: 執行規劃、推理與行為生成。
  6. REFLECTION: 輸出前進行衝突檢查與神聖反思。
  7. RESPONSE: 產生最終回應、計畫或建議。
  8. MEMORY_UPDATE: 更新記憶聖殿並等待下一輪輸入。

5. 系統開發藍圖 (Strategic Roadmap)

  • Phase 1: 核心運行環境 (FastAPI, Global State, Controller)
  • Phase 2: 記憶系統 (長期記憶存取)
  • Phase 3: 進階控制 (反思引擎, 策略引擎)
  • Phase 4/5: 多 Agent 協作與完整 AI 作業系統
